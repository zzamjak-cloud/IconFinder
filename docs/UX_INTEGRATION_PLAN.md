# IconMaker UX·기능 통합 방향 계획

Search / Editor 두 탭으로 갈라진 기능을 하나의 흐름으로 통합하기 위한 방향성 문서.

## 0. 왜 이렇게 되었나 (진단의 출발점)

Editor 탭은 StyleStudio의 SVG 세션 기능을 **패널째 이식**한 결과다(`SVG_WORKSPACE_MERGE_PLAN.md`).
이식 당시 "기존 IconMaker를 건드리지 않는다"가 원칙이었기 때문에 검색·보관·내보내기가
의도적으로 분리 구현되었고, 그 부채가 지금의 UX 불일치로 드러난 것이다.
즉 이것은 설계 실수가 아니라 **이식 후 통합 단계가 남아 있는 상태**다.

## 1. 현재 구조 진단 — 같은 일을 하는 두 벌의 시스템

| 기능 | Search 탭 | Editor 탭 | 문제 |
|------|-----------|-----------|------|
| 검색 | `iconifyApi.searchIcons` (limit 100, 컬렉션 드롭다운 필터) | `svgIconSearch` (48개/페이지, 페이지네이션, 소스팩 5종 필터, 한글→영문 쿼리 확장) | 같은 Iconify API 위에 검색기 2개. 한글 검색은 Editor에서만 되고, 페이지네이션도 Editor에만 있음 |
| 보관 | `favorites: string[]` — 아이콘 **이름만** 저장 | 금고(vault) — SVG 원문·카테고리·스타일·`favorite` 플래그까지 저장 | 보관 개념이 두 벌. 심지어 **즐겨찾기도 두 벌** (Search의 favorites ↔ Editor 아이콘의 favorite 플래그) |
| 내보내기 | ExportPanel (포맷/크기/색) + 즐겨찾기 일괄 내보내기 | 스타일 적용 SVG/PNG 저장, SVG/HTML/CSS 복사, 카테고리 스프라이트 | 파이프라인 2개. Search에서 스타일 불가, Editor에서 크기/색 일괄 지정 불가 |
| 필터 | Iconify 전체 컬렉션 목록 드롭다운 | 큐레이션 소스팩 (game/ui/pixel/material/emoji) | 동일 목적(범위 좁히기), 서로 다른 UI·다른 어휘 |
| 명칭 | "검색" | "에디터" | 실제로는 둘 다 검색+보관+내보내기를 함. 이름이 역할을 설명하지 못함 |

## 2. 목표 상(target picture) — 단일 플로우

사용자 여정을 하나로 정의한다:

> **찾는다 → 담는다 → (필요하면) 다듬는다 → 내보낸다**

이 여정을 화면 하나가 감당한다. **3-컬럼 단일 워크스페이스**:

```
┌──────────────┬──────────────────────────────┬──────────────────┐
│  보관함       │  검색                         │  디테일           │
│  (Library)   │  [검색어_______] [스코프 칩]    │                  │
│              │                              │  미리보기          │
│  카테고리 목록 │  검색 결과 그리드(가상화)        │                  │
│  ├ 전투       │  ─────────────────────────    │  ── 퀵 내보내기 ── │
│  ├ 아이템     │  보관된 아이콘(선택 카테고리)     │  포맷/크기/색      │
│  ├ …         │                              │  [SVG] [PNG]     │
│  ☆ 즐겨찾기   │                              │  ── 스타일 ▸ ──   │
│  (스마트 뷰)  │                              │  (펼치면 현재      │
│              │                              │   Editor 컨트롤)  │
└──────────────┴──────────────────────────────┴──────────────────┘
```

현재 **Editor 레이아웃이 이미 이 구조와 거의 같다** (v0.3.3의 상하 분할 + 사이드바 + 우측 패널).
따라서 방향은 "둘을 절충"이 아니라 **Search 탭을 Editor 골격에 흡수**하는 것이다.

### 2.1 검색 — 하나로

- 검색 서비스 단일화: `svgIconSearch`를 일반화하여 유일한 검색 경로로 만든다.
  한글 쿼리 확장·페이지네이션이 전역 검색 혜택이 된다.
- 범위 선택은 **스코프 칩** 하나로 통합:
  `전체` | 큐레이션 팩 5종(기존 소스팩) | `컬렉션 선택…`(기존 드롭다운을 칩 뒤로 이동)
- 소스팩은 결국 prefix 묶음이므로 컬렉션 필터의 프리셋일 뿐이다 — 같은 파라미터로 수렴 가능.

### 2.2 보관 — 보관함(Library) 하나로

- 금고(vault)를 **보관함**으로 승격하고, Search의 favorites를 흡수한다.
- 통합 데이터 모델(기존 `SvgWorkspaceIcon` 확장):
  - `svg`를 **선택적**으로 — 이름만 아는 라이트 항목(구 즐겨찾기)은 선택 시 지연 로드
  - `favorite: boolean`은 이미 존재 — 이것이 유일한 즐겨찾기가 된다
- **즐겨찾기 = 카테고리가 아니라 스마트 뷰**: 사이드바 최상단 `☆ 즐겨찾기`는
  전체 카테고리에서 `favorite=true`만 모아 보여준다. "빠른 담기"(별 클릭)는
  `미분류` 카테고리 + favorite 플래그로 저장 → 나중에 드래그로 분류.

### 2.3 내보내기 — 디테일 패널 하나로

- 아이콘 선택(검색 결과든 보관함이든) → 우측 디테일 패널.
- 기본 화면은 **퀵 내보내기** (현 ExportPanel의 포맷/크기/색 + 기본 폴더 자동 저장).
- `스타일` 섹션을 펼치면 현재 Editor의 전체 컨트롤(스타일 종류·색·효과·베벨).
- 일괄 내보내기는 "즐겨찾기 전용"에서 **선택 항목/카테고리 단위**로 일반화.
  스프라이트 내보내기는 카테고리 단위 기능으로 유지.

### 2.4 네이밍

- 탭이 사라지므로 "검색/에디터" 명칭 문제 자체가 소멸.
- 과도기(Phase 1)에 탭을 유지하는 동안은 `탐색(Discover)` / `보관함(Library)`으로 개칭 —
  현재 i18n 체계에서 키 2개 수정으로 끝난다.

## 3. 단계별 로드맵

### Phase 1 — 엔진 통합 (UI 변화 없음, 리스크 낮음)

| # | 작업 | 영향 파일 |
|---|------|-----------|
| 1 | 검색 서비스 단일화: `svgIconSearch` 일반화, Search 탭도 이것을 사용 | `lib/svgIcon/svgIconSearch.ts`, `hooks/useIconSearch.ts`, `services/iconifyApi.ts` |
| 2 | 보관함 모델 확장: `svg` 선택화(지연 로드), 라이트 항목 지원 | `types/svgIcon.ts`, `services/storageService.ts` |
| 3 | favorites → 보관함 마이그레이션 (`미분류` + favorite 플래그, 이름만 이관) | `storageService.ts` (templateKey 마이그레이션과 동일 패턴) |
| 4 | 백업 포맷 v2 (favorites 키 흡수, 하위 호환 읽기 유지) | `storageService.ts` |

기존 사용자 데이터 보호가 핵심. templateKey 마이그레이션과 같은 방식
(로드 시 1회 변환, 변경 시에만 저장)을 재사용한다.

### Phase 2 — UI 통합 (구조 변경)

| # | 작업 | 비고 |
|---|------|------|
| 1 | 탭 제거, 단일 워크스페이스로 수렴 | Editor 골격 유지, Search 탭 삭제 |
| 2 | 스코프 칩 (소스팩 + 컬렉션 선택 통합) | CategoryDropdown을 칩의 서브메뉴로 |
| 3 | 검색 결과 그리드에 `IconGrid`의 가상화·컬럼 슬라이더 이식 | 큰 그리드 탐색 경험 보존 |
| 4 | 디테일 패널: 퀵 내보내기 기본 + 스타일 아코디언 | ExportPanel 흡수 후 삭제 |
| 5 | 일괄/스프라이트 내보내기를 선택·카테고리 기반으로 일반화 | BatchExportDialog 재배선 |
| 6 | 사이드바에 `☆ 즐겨찾기` 스마트 뷰 | |

### Phase 3 — 정리

- 죽은 코드 제거: `SearchBar`(검색창은 워크스페이스로), `FavoritesPanel`(이미 미사용), `ExportPanel`, favorites 전용 훅
- i18n 키 정리: 탭 키 제거, 신규 키 추가 — **키 누락은 컴파일 에러로 강제되므로 11개 언어 누락 위험 없음**
- 빈 상태/온보딩 문구, README·CHANGELOG 갱신

## 4. 리스크와 대응

| 리스크 | 대응 |
|--------|------|
| `SvgIconPanel.tsx`(1,830줄)가 upstream에서 활발히 변경 중 — v0.3.2/0.3.3에서 827줄 재작성된 전례 | **feature 브랜치에서 진행 + 작업 기간 main의 해당 파일 변경 동결 조율.** Phase 2 시작 전 main 최신 병합 필수 |
| 기존 사용자의 favorites·워크스페이스 데이터 | Phase 1 마이그레이션을 별도 릴리스로 먼저 배포해 데이터 계층을 안정화한 뒤 UI를 바꾸는 순서 |
| 단일 화면의 밀도 상승 (Search 탭의 "넓은 그리드" 경험 훼손 우려) | 보관함 사이드바 접기 + 디테일 패널은 선택 시에만 표시 → 미선택 상태에서는 사실상 현재 Search 탭과 동일한 전면 그리드 |
| 검색 범위 통합 시 라이선스 안내 정합성 | 스코프 칩에 라이선스 뱃지 연동 (기존 LicenseDialog 데이터 재사용) |

## 5. 이 계획이 의도적으로 하지 않는 것

- 스타일 엔진(`svgIconStyle.ts`)·워크스페이스 저장 구조는 손대지 않는다 — 문제는 겉의 정보 구조이지 엔진이 아니다.
- 다중 워크스페이스/세션 개념 재도입 없음 (StyleStudio에서 이미 제외하기로 결정했던 범위).

## 6. 미결정 질문 (구현 착수 전 확인)

1. **탭 완전 제거 vs 유지**: 권고는 제거(단일 워크스페이스)이나, 두 사용 모드(빠른 탐색 vs 정리 작업)를 탭으로 남기고 싶다면 Phase 2를 "Discover/Library 개칭 + 검색·보관 공유"까지만 진행하는 축소판도 성립한다.
2. **퀵 내보내기의 기본값**: 스타일 미적용 원본 기준(현 Search 탭 동작)인지, 마지막 적용 스타일 기준인지.
3. **`미분류` 카테고리**: 자동 생성 카테고리로 둘지, 카테고리 없는 상태(inbox)를 허용할지.
